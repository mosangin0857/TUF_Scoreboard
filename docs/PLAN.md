# TUF 스코어보드: 기획과 기술스택

TUF 클랜 BJ들이 **다운받아 설치만 하면 바로 쓰는** 스코어보드 프로그램.
웹 호스팅(Vercel 등)이나 외부 서버 없이 **설치형 프로그램 하나**로 동작한다.

---

## 1. 핵심 개념: 프로그램 하나에 서버를 넣는다

```
┌──────────────── TUF_Scoreboard.exe (BJ PC에서 실행) ────────────────┐
│                                                                     │
│   [조작 창]  ──▶  [내장 미니 서버 127.0.0.1:7777]  ──▶  [오버레이 화면] │
│   팀명/점수 입력      상태 저장 + 실시간 전달            /overlay         │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
                                   ▲
                                   │  프릭샷 웹(브라우저) 소스에 URL 등록
                                   │  http://127.0.0.1:7777/overlay
                              [프릭샷]
```

- 오버레이 주소가 `http://...` 형태라도 **인터넷 웹사이트가 아니다.** 프로그램이 켜져 있는 동안 BJ 본인 PC 안에서만 열리는 주소다.
- Vercel·호스팅 비용, 서버 관리, 인터넷 딜레이가 모두 없다. BJ마다 각자 PC에서 독립적으로 동작한다.
- 프로그램이 꺼지면 오버레이도 사라지고, 다시 켜면 자동으로 다시 연결된다.

### 오버레이를 프릭샷에 띄우는 방식 비교

| 방식 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **A. 내장 서버 + 웹 소스** (추천) | 위 그림 방식. 앱에서 URL 복사 후 프릭샷 웹 소스에 붙여넣기 | 진짜 투명 배경, 애니메이션·로고 자유, 창을 가려도 됨 | 처음 한 번 URL 등록 필요 |
| B. 오버레이 전용 창 + 창 캡처 | 앱이 초록 배경 창을 띄우고, 프릭샷에서 창 캡처 + 크로마키 | URL 개념이 없음 | 글자 테두리 초록 번짐, 창 최소화 시 안 보임, 설정이 오히려 더 복잡 |
| C. 텍스트 파일 출력 | 앱이 .txt로 쓰고 방송툴 텍스트 소스가 읽음 | 가장 단순 | 디자인 불가, 프릭샷 지원 여부 불확실 |
| D. 가상 카메라 | 앱이 가상 웹캠 장치로 영상 출력, 프릭샷에서 웹캠 소스로 추가 | 프로그램이 장치 목록에 뜸 | 투명 불가(크로마키 필요), 드라이버 설치·관리자 권한 필요, 백신 경고 위험 |
| E. 방송툴 플러그인 | 프로그램이 프릭샷 소스 종류로 직접 등록 | 가장 네이티브 | 프릭샷은 공개 플러그인 SDK가 없어 사실상 불가 (OBS만 가능) |

> 창 캡처·가상 카메라처럼 "영상"으로 넘기는 방식은 투명(알파) 정보가 전달되지 않는다.
> 투명 배경을 그대로 넘길 수 있는 경로는 웹 소스뿐이다. 알림 서비스(투네이션·트윕)가 모두 웹 소스를 쓰는 이유가 이것이다.
> 결론: A를 기본으로 하고, B(오버레이 창 + 크로마키)를 설정에서 켤 수 있는 예비 모드로 함께 제공한다.

→ **A를 기본**으로 하고, 앱에 "프릭샷 설정 가이드(스크린샷)"와 **URL 복사 버튼**을 넣어 1분 안에 세팅이 끝나게 한다.

## 1-1. 내장 서버 켜고 끄기 (생명주기)

**원칙: 서버 = 프로그램. BJ는 서버를 따로 켜고 끄지 않는다.**
서버는 Electron 메인 프로세스 안에서 돌린다(별도 프로세스 X). 그래서 앱이 켜지면 서버도 켜지고, 앱이 꺼지면 서버도 꺼진다. 백그라운드에 서버만 남는 일(좀비 프로세스)이 없다.

| 상황 | 동작 |
|---|---|
| 앱 실행 | 서버 자동 시작 → 저장된 점수 불러오기 → 트레이 아이콘 표시 |
| 창 X 버튼 | **종료가 아니라 트레이로 숨김** (디스코드 방식). 서버는 계속 동작, 방송 유지 |
| 트레이 → 종료 | "방송 중이면 스코어보드가 사라집니다" 확인 후 상태 저장 → 서버 종료 → 앱 종료 |
| 앱 두 번 실행 | 중복 실행 차단(single instance), 기존 창을 앞으로 가져옴 → 포트 충돌 방지 |
| 윈도우 부팅 | (설치 시 옵션, 기본 ON) 트레이로 자동 실행 → 프릭샷보다 항상 먼저 켜져 있음 |
| 포트 사용 중 | "7777 포트를 다른 프로그램이 사용 중" 안내 + 다른 포트 선택 |
| 앱 비정상 종료 | 오버레이는 마지막 화면 유지 + 재연결 시도, 앱 재실행 시 자동 복구 |

### 핵심 문제: 켜는 순서
- **앱 → 프릭샷 순서**: 문제없음.
- **프릭샷 → 앱 순서**: 프릭샷이 오버레이 주소를 여는 시점에 서버가 없어서 페이지 로드에 실패한다.
  한 번 실패한 웹 소스는 스스로 다시 시도하지 않을 수 있다 → BJ가 소스를 새로고침해야 함 (**가장 흔한 문의 예상**).

### 해결책 (우선순위 순)
1. **윈도우 시작 시 자동 실행 (트레이)**: 서버가 항상 먼저 떠 있으므로 순서 문제 자체가 없다. 대기 중 CPU 사용은 거의 0.
2. **오버레이를 로컬 파일로 등록 (프릭샷이 지원할 경우)**: 오버레이 HTML을 설치 폴더의 파일로 열고, 페이지 안 JS가 `ws://127.0.0.1:7777`에 재연결을 계속 시도한다.
   → 앱이 늦게 켜져도 알아서 붙는다. 순서가 완전히 무관해진다.
3. **오버레이 자동 재연결**: 페이지가 한 번 로드된 뒤에는 앱을 껐다 켜도 1~2초 안에 자동 복구된다. 끊긴 동안에는 마지막 점수를 그대로 표시한다.
4. 1·2가 모두 안 되면 가이드에 "앱 먼저 실행, 안 보이면 소스 새로고침" 안내.

→ **1단계 검증 항목에 추가**: 프릭샷에서 (a) 서버가 꺼진 상태로 웹 소스를 열면 어떻게 보이는지(빈 화면 vs 에러 페이지), (b) 나중에 서버를 켜면 자동으로 붙는지, (c) 로컬 파일 HTML을 소스로 등록할 수 있는지.

## 1-2. 프릭샷에서 크기 조절

기존 스코어보드(TFPL_S4/bj)와 같은 방식을 그대로 쓴다.
- 오버레이 페이지에 **자동 스케일**을 넣는다: 기준 크기(종최 SB1 317×100 등)를 소스 창 크기에 맞춰 `transform: scale()`로 확대·축소.
- BJ는 프릭샷 소스의 너비·높이만 바꾸면 스코어보드가 비율을 유지한 채 커지거나 작아진다. 글자가 다시 그려지므로 흐려지지 않는다.
- 소스 테두리를 마우스로 끌어 늘리는 방식도 되지만, 소스 크기보다 크게 늘리면 흐려질 수 있다 → 가이드에 "소스 크기로 조절" 권장.
- 추가 편의 기능(선택): 앱 설정에 스코어보드별 **크기 슬라이더**와 **권장 소스 크기 복사** 버튼.

## 2. 기술스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 앱 프레임워크 | **Electron** | 윈도우 설치 프로그램 생성, 서버 내장 쉬움, 단축키·트레이 지원, 자료 많음 |
| 내장 서버 | Node.js (Express) + **ws** (WebSocket) | 오버레이 파일 제공 + 조작 즉시 전달 |
| 조작 UI | React + Vite | 버튼·입력 많은 화면 만들기 편함 |
| 오버레이 | 순수 HTML/CSS/JS | 가볍고 방송툴 브라우저 호환성 최고 |
| 설정/상태 저장 | JSON 파일 (`%APPDATA%\TUF_Scoreboard`) | 재시작해도 점수·팀 목록 유지 |
| 설치 파일 | **electron-builder (NSIS)** | `TUF_Scoreboard_Setup.exe` 한 개 → 더블클릭 설치, 바탕화면 아이콘 |
| 자동 업데이트 | **electron-updater + GitHub Releases** | 새 버전 올리면 BJ 앱이 알아서 업데이트 → 재배포 수고 없음 |
| 배포 채널 | GitHub Releases (무료) → 클랜 디스코드/카페에 링크 공유 | 다운로드 링크 고정, 버전 관리 |

### 대안 검토
- **Tauri**: 설치파일이 5~10MB로 작다(Electron은 약 80~100MB). 다만 Rust 개발환경이 필요하다. 용량이 문제가 되면 나중에 옮길 수 있다.
- **Python + PyInstaller**: 백신 오탐(바이러스로 잘못 인식)이 잦아 BJ 배포용으로는 비추천.
- **C# WPF**: 윈도우 전용으로 가볍지만 오버레이 디자인·애니메이션은 웹 기술이 훨씬 유리.

## 3. BJ 입장에서 쉬워야 할 것 (UX 원칙)

1. **설치**: Setup.exe 더블클릭 → 끝. 추가 설치(Node 등) 없음.
2. **첫 실행 가이드**: "프릭샷에 추가하는 법" 3단계 화면 + [URL 복사] 버튼.
3. **조작**: 큰 +1 / -1 버튼, 팀명 클릭해서 바로 수정, 좌우 교체 버튼 하나.
4. **단축키**: 게임 화면 보면서도 조작 가능 (예: F1 = A팀 +1, F2 = B팀 +1, 사용자 변경 가능).
5. **미리보기**: 조작 창 안에서 방송에 나갈 모습을 그대로 확인.
6. **TUF 프리셋 내장**: 클랜원/팀 목록, 종족, 맵 목록을 미리 넣어두고 드롭다운으로 선택.
7. **자동 저장**: 앱을 실수로 꺼도 점수 유지.
8. **자동 업데이트**: BJ가 신경 쓸 필요 없음.

## 4. 배포 시 주의사항

- **Windows SmartScreen 경고**: 코드서명 안 된 exe는 첫 실행 때 "Windows의 PC 보호" 창이 뜬다.
  - 무료로 가려면 "추가 정보 → 실행" 안내 이미지를 배포글에 첨부한다.
  - 경고를 없애려면 코드서명 인증서(유료)가 필요하다. 초기엔 안내로 대응하고, 사용자가 늘면 검토한다.
- **방화벽 팝업 방지**: 서버를 `127.0.0.1`에만 열면 윈도우 방화벽 허용 창이 안 뜬다(`0.0.0.0`은 뜬다).
- **포트 충돌**: 기본 7777, 사용 중이면 설정에서 바꿀 수 있게 한다(바꾸면 프릭샷 URL도 다시 등록).
- **폰트/이미지 전부 앱에 포함**: 인터넷 없이도 오버레이가 정상 표시되게.
- **오버레이 자동 재연결**: 앱을 재시작해도 프릭샷에서 새로고침할 필요 없게.

## 5. 기능 목록

**v1 (MVP)**
- A/B 팀·선수명, 점수(+1/-1/직접입력), 세트/경기 정보 텍스트
- 좌우 교체, 리셋, 오버레이 표시/숨김 (애니메이션)
- URL 복사 버튼, 프릭샷 설정 가이드
- 전역 단축키, 자동 저장

**v2**
- 로고·팀컬러, 종족/맵 표시, TUF 프리셋
- 오버레이 테마 여러 개 (TUF / TFPL 등)
- 타이머, 자동 업데이트

**v3 (선택)**
- 같은 와이파이 휴대폰으로 조작
- 스트림덱 연동

## 6. 폴더 구조 (예정)

```
TUF_Scoreboard/
├─ docs/PLAN.md
├─ package.json
├─ electron/            메인 프로세스 (창, 트레이, 단축키, 내장 서버)
├─ src/control/         조작 UI (React)
├─ src/overlay/         송출용 오버레이 (HTML/CSS/JS)
├─ assets/              로고, 폰트, 아이콘
└─ build/               설치파일 설정
```

## 7. 작업 순서

1. **프릭샷 검증**: 테스트용 오버레이를 띄워 프릭샷 웹 소스에서 투명 배경이 정상인지 확인 (가장 먼저)
2. **MVP 코어**: Electron + 내장 서버 + 조작 창 + 오버레이 → 실시간 반영 확인
3. **오버레이 디자인**: TUF 브랜딩
4. **설치파일 빌드**: Setup.exe 생성 → 다른 PC(클랜원 1~2명)에서 설치 테스트
5. **v2 기능 + 자동 업데이트**
6. **배포**: GitHub Releases + 설치/사용 가이드 이미지 → 클랜 공지
